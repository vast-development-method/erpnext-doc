# Document conversions

A conversion prepares a business document from a specific predecessor. A purchase order line can be received, billed or sent for subcontracting. Each destination uses a different remaining quantity and a different posting event. Start with a document or business area below.

## Reading a mapping

The source and destination columns identify [entities and fields](../../schema/README.md). The shared fields `record_identifier`, `entity_type`, `owning_record_identifier`, `owning_entity_type` and `lifecycle_state` are resolved from the record envelope. Named transfers are assignments during preparation. A calculation or eligibility rule in the accompanying text can narrow the selected rows or replace an initial value. A header reference identifies the transaction. Its child-row reference distinguishes repeated items, partial fulfilments and returns.

A collection may be rebuilt from selected lines or populated only if the destination is empty. A zero-valued commercial line can participate when its contract is price-only. The authorised destination action determines persistence and posting. Submitting a predecessor does not itself issue every listed successor.

[Worked conversions](worked-conversions.md) follow partial purchasing, installation, production and journal reversal from source row through destination effects.

[Competing commitments](competing-commitments.md) follows the same stock through reservation, delivery, consignment, order closure and return, including the records that must be re-read before a second command.
