# Group companies and currency translation

The consolidated report accepts a parent company, date or fiscal-year bounds, a statement choice, an optional presentation currency and an accumulate-in-group flag. Company columns are drawn from the parent and its descendants in tree order. With accumulation off each column contains only that company's entries. With accumulation on each column includes its entire subtree, so a subsidiary amount can correctly appear in both parent and child columns. The total in accumulated mode uses the selected group company's value. Adding those columns would count the subsidiary twice. Without an explicit presentation currency, each column uses that company's base currency; summary cards for mixed-currency companies restrict the summary to the selected company. Independently scope the account data visible to the caller.

Account matching uses the account number plus account name when numbered, otherwise the account name alone. Construct a mapping from each local account identity to this key before building the shared parent hierarchy. Two companies can have identically numbered accounts with different names; these are different keys here. A child-only account can contribute to the group column. Report readers need both each original legal entity's amount and each reporting column's unit. The aggregation does not supply ownership-percentage weighting, minority-interest calculations or automatic elimination of intercompany balances. Agreements to implement such rules need separate elimination journals or an explicitly defined report policy.

## Translating a signed entry

Use debit minus credit as the working sign. Resolve the reporting column's currency first. If it equals the source company's base currency, preserve the amount. For a foreign source compute the closing-rate equivalent at the period end. Assets and liabilities outside the equity class take that closing amount. An income-statement entry, equity root, or equity account type uses the transaction-rate measurement. Prefer stored reporting-currency debit less credit when the company's configured reporting currency equals the target and a reporting amount is present. Otherwise translate at the posting-date rate. For each transaction-rate entry add `closing equivalent − transaction equivalent` to the column's signed reserve. For entries before report start also add this difference to the column opening reserve. Each column must calculate its own reserve.

Balance-sheet queries do not ordinarily fetch income and expenses. Include their unclosed translation differences in the reserve. If the latest submitted, completed close through report end falls within the requested interval, start this P&L subtotal on the following day. Closed earnings are already in translated equity. A reserve with a nonzero amount at three decimal places gets an equity row. For the cash-flow reconciliation the displayed reserve adjustment uses the negated working reserve. Persisting an exchange journal merely for generating these report rows would alter the ledger.

## Acceptance example

The parent reports in NAD. Its own books contain a cash sale of N$30. A foreign subsidiary makes a USD 100 cash sale, debiting its bank and crediting sales. The effective reporting-date conversion is N$18 per USD, and the transaction-rate equivalent stored for the sales credit is N$1,600. The parent accumulated column must reconcile assets of N$1,830, provisional profit of N$1,630, and a credit translation reserve of N$200. The subsidiary's own unconverted column still has USD 100 cash, USD 100 profit, and zero reserve. With the parent set to own-company-only, its profit is N$30 and its reserve is zero. Repeating the case after clearing the older row's stored reporting amounts must yield the same result when the posting-date rate is N$16 per USD. If the posting-date lookup instead returns N$15, profit becomes N$1,530 and the credit reserve N$300. [Structured tests](examples/group-translation.json)
