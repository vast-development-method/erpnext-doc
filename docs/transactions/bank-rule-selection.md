# Bank statement rule evaluation

A bank statement line holds company, bank account, withdrawal, deposit, description, document state, reconciliation state, evaluated flag and optional matched rule. A rule belongs to one company, has a numeric priority and can suggest a bank journal, party payment or transfer. The durable result of evaluation is a suggestion on the statement line. Posting or matching an actual payment and setting its clearance remain separate [treasury operations](treasury-and-reconciliation.md).

## Configuration and selection

An unset or zero priority on insert receives one more than the highest existing priority for the company, starting at one. After deletion, renumber that company's remaining rules consecutively in ascending prior priority. The delete hook attempts to clear stale rule links; it suppresses cleanup errors, so do not assume that cleanup of all affected statements succeeded. Equal explicit priorities have no specified final tiebreak. For payment suggestions require party type, party and party account. For a single-account bank entry require an account. A split entry needs account rows in the same company. Its final row reserves the balancing amount and may supply neither debit nor credit. Earlier rows accept constants or restricted arithmetic over transaction amount. Rule validation exercises expressions with an amount of one. A valid expression can still fail for some transaction amounts; a replacement must handle an unsuccessful amount evaluation before submitting a voucher.

1. Reject a company mismatch. For a withdrawal-specific rule require a nonzero withdrawal; for a deposit-specific rule require a nonzero deposit. Evaluate the withdrawal amount when nonzero, otherwise the deposit.
2. Enforce configured nonzero minimum and maximum values inclusively. The stored zero value in either field means unbounded on that side. Refuse configuring a nonzero minimum greater than a nonzero maximum.
3. After the company, direction and amount gates pass, compare the line description against each configured description condition, returning true at the **first** match. The four operations are contains, starts with, ends with, and regular-expression search. Lowercase both description and condition value before matching; regular expressions are also lowercased as text. Validate regular-expression syntax on rule write. Empty condition collection returns false even if all range and direction gates pass. An empty contains/starts/ends comparison value would match any string if permitted by record validation.
4. Evaluate rules from lowest numeric priority upward and stop at the first matching rule. This ordering differs from tax-template selection. Persist the matched identity or null, and mark the line evaluated even when all candidates fail. If there are no rules at all the batch returns without marking statements.

The explicit run command requires write permission on bank transactions and queues a job. Its worker loads submitted `Unreconciled` statements and, in ordinary mode, only unevaluated statements. A forced run includes already evaluated lines and can clear an obsolete match. The worker filters company inside each rule comparison. The scheduled run checks the accounts setting for automatic evaluation. In the operator interface choosing the matched rule opens the appropriate journal, payment or transfer action. Evaluating or reevaluating alone changes neither bank balance nor allocated amount. A replacement should independently authorize any eventual posting under its own voucher contract.

Suppose an unreconciled withdrawal of 150.00 reads `MONTHLY SERVICE FEE`. Rule 1 for the same company accepts withdrawals from 100.00 through 150.00 and matches descriptions ending in `fee` or containing `charge`. Rule 2 accepts any amount containing `service`. Rule 1 wins at the inclusive upper bound. After its maximum is lowered to 149.99, an ordinary repeat preserves the earlier suggestion because the line is already evaluated. A forced run selects rule 2. If the line has since been reconciled even a forced run omits it. See `FIN-014`–`FIN-016` in the [vectors](examples/financial-decisions.json).
