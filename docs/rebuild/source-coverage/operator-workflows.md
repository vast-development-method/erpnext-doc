# Desk workflows and acceptance examples

## Resolve a clerk's navigation

The ERP dock opens the Accounts sidebar. Its first two links have different destinations. **Home** points to the Accounting workspace and **Dashboard** points to the Accounts dashboard. The dashboard's **Total Incoming Bills** card then selects Purchase Invoice records. Captions, destination record type and destination ID are separate inputs. Translating “Home” must preserve the workspace identity, and opening the dashboard must preserve the card's invoice source. ## Reconcile Total Incoming Bills

The card sums `base_net_total` for submitted purchase invoices of the current default company. Its dynamic posting-date bounds come from the current fiscal year. If that value is absent, the declaration supplies January 1 through December 31 of the current year. The server aggregates the permitted document query. Its monthly comparison repeats the current filters and adds a strict **creation timestamp before one month ago** condition. A backdated invoice can affect the current value while falling outside the comparison. [Card declaration](https://github.com/frappe/erpnext/blob/886ab6ae187244e7f1b852393384ab6019d56264/erpnext/accounts/number_card/total_incoming_bills/total_incoming_bills.json#L2-L21) · [Filter resolver](https://github.com/frappe/frappe/blob/199a0385c00e572664a099a57a00be6ce7404eeb/frappe/public/js/frappe/utils/dashboard_utils.js#L204-L249) · [Aggregation and comparison](https://github.com/frappe/frappe/blob/199a0385c00e572664a099a57a00be6ce7404eeb/frappe/desk/doctype/number_card/number_card.py#L125-L204)

The [machine-readable example](indicator-example.json) fixes the clock at November 18, 2026 at 09:00 and uses Windhoek's March-to-February fiscal year. Its seven input rows include two foreign transaction currencies, a negative base amount, a draft, another company, a pre-year posting and a row hidden from the query. Eligible base amounts of 200, 100 and −50 give **NAD 250**. The invoice contributing 100 has a September posting date but was created exactly at the October 18 09:00 cutoff. It is excluded from the previous value. That leaves 200 and a **25% increase**.

| Configuration | Current | Previous | Displayable change |
|---|---:|---:|---:|
| Fiscal year supplied | 250 | 200 | 25% |
| Fiscal year missing, use calendar year | 325 | 275 | About 18.18% |
| Zero prior aggregate | 0 | 0 | No percentage value |

The pinned client filter resolver and server aggregation and comparison functions produced these results in isolation. The fixture supplies company, clock, currency and row visibility. SQLite executed the requested filtering and sum. The [machine-readable example](indicator-example.json) also records the resolved date, company and four ageing boundaries for the separate Accounts Payable Ageing chart. A full website run requires actual site permissions, chart rendering and the selected company's data.

## Complete accounting onboarding

The accounting guide has nine ordered steps. The first three are required. Reviewing the chart of accounts and taxes are page actions. Adding a bank account is a record action with `is_company_account = 1`. Entering an invoice and opening the general ledger are optional. The guide declares Accounts Manager and Accounts User. The framework adds System Manager as an implicit allowed role. The step-details response translates the title, description and action caption while retaining the step ID and reference record. [Accounting guide](https://github.com/frappe/erpnext/blob/886ab6ae187244e7f1b852393384ab6019d56264/erpnext/accounts/module_onboarding/accounting_onboarding/accounting_onboarding.json) · [Bank account step](https://github.com/frappe/erpnext/blob/886ab6ae187244e7f1b852393384ab6019d56264/erpnext/accounts/onboarding_step/add_bank_account/add_bank_account.json) · [Role and completion rules](https://github.com/frappe/frappe/blob/199a0385c00e572664a099a57a00be6ce7404eeb/frappe/desk/doctype/module_onboarding/module_onboarding.py#L38-L68) · [Localized details](https://github.com/frappe/frappe/blob/199a0385c00e572664a099a57a00be6ce7404eeb/frappe/desk/doctype/onboarding_step/onboarding_step.py#L156-L195)

**Acceptance example.** Two authorized clerks work in different languages. One imports a Bank Account record for a customer. With no explicit completion or skip, the company-bank-account step remains open. Import a company account and both clerks can observe that the work is done. The check searches site records using declared route-option fields and primitive values. A Create Entry step targeting a submittable record also requires submitted status. Once the first two required actions are marked complete and the company account exists, the guide can complete with optional steps still open. Persistence of the guide-complete event is queued after commit. Resetting the guide clears its stored completion and skip flags. Existing qualifying business records can still satisfy their steps on the next read. [Work recognition](https://github.com/frappe/frappe/blob/199a0385c00e572664a099a57a00be6ce7404eeb/frappe/desk/doctype/onboarding_step/onboarding_step.py#L58-L94) · [Record filters and validation](https://github.com/frappe/frappe/blob/199a0385c00e572664a099a57a00be6ce7404eeb/frappe/desk/doctype/onboarding_step/onboarding_step.py#L121-L153) · [Reset and completion](https://github.com/frappe/frappe/blob/199a0385c00e572664a099a57a00be6ce7404eeb/frappe/desk/doctype/module_onboarding/module_onboarding.py#L41-L79)

## Read settings from a business record

The Party Account map exposes two fields from Accounts Settings, one for common party accounting and another for invoices in multiple currencies against one party account. A standard map has a module-qualified identity. Each affected DocType can have one custom map. Activating one map deactivates its siblings. If deactivating it leaves remaining siblings without an active map, the controller prefers a standard sibling. Read the actual setting value from its source single document. The map supplies a field reference, while the [settings register](settings-map.tsv) carries its declared metadata. [Party Account map](https://github.com/frappe/erpnext/blob/886ab6ae187244e7f1b852393384ab6019d56264/erpnext/accounts/doctype_settings_map/party_account.json) · [Map selection](https://github.com/frappe/frappe/blob/199a0385c00e572664a099a57a00be6ce7404eeb/frappe/core/doctype/doctype_settings_map/doctype_settings_map.py#L120-L179)

**Acceptance example.** Give an operator read access to Party Account and read-only access to the relevant level on Accounts Settings. The settings response can show the two source values with translated labels and stable field names. Each field's write flag is false. A user without source read permission receives no fields from that source. Without read permission on the target, the existence query returns false and full resolution denies access. Activate a site-owned map that exposes only one field. The next authorized read shows that single field. Deactivate the site map with a single standard sibling present and both shipped mappings become available again. The actual update path must still check write permission at save time. [Target and source access](https://github.com/frappe/frappe/blob/199a0385c00e572664a099a57a00be6ce7404eeb/frappe/desk/doctype_settings/settings_map.py#L21-L86) · [Translated field projection](https://github.com/frappe/frappe/blob/199a0385c00e572664a099a57a00be6ce7404eeb/frappe/desk/doctype_settings/settings_map.py#L86-L129)
