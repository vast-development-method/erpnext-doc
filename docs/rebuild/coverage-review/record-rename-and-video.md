# Record renaming and video tracking

A master-data administrator can replace a record key or merge two identities. A content editor can register a video and optionally refresh engagement counts from its provider. The [Utilities record dictionary](../model/modules/erpnext-utilities.md) supplies their field definitions. The source links below identify the ERPNext 16.60.0 and Frappe 16.60.1 implementations used for this review.

## Rename or merge records from an attachment

| Stage | Decision and observable result |
|---|---|
| Select target | The singleton Rename Tool grants its standard permissions to System Manager. Upload requires write access to the tool and target record type. The target must exist, permit renaming and belong to a module other than Core. The framework checks write access again on the source record and, for a merge, the destination record. [Tool metadata](https://github.com/frappe/erpnext/blob/886ab6ae187244e7f1b852393384ab6019d56264/erpnext/utilities/doctype/rename_tool/rename_tool.json#L32-L51) · [Admission](https://github.com/frappe/erpnext/blob/886ab6ae187244e7f1b852393384ab6019d56264/erpnext/utilities/doctype/rename_tool/rename_tool.py#L44-L75) · [Record checks](https://github.com/frappe/frappe/blob/199a0385c00e572664a099a57a00be6ce7404eeb/frappe/model/rename_doc.py#L334-L393) |
| Admit a file | Select an attachment belonging to this singleton. An explicit file URL narrows the search. Otherwise select the most recently created matching attachment. Reject a missing attachment. Parse all CSV rows, schedule one long-queue job per consecutive block of up to 500 rows after request commit, clear the singleton's attachment field if it still holds that URL, and delete the consumed file. Each job receives its rows as input. An empty parsed list creates zero jobs. [Upload and pagination](https://github.com/frappe/erpnext/blob/886ab6ae187244e7f1b852393384ab6019d56264/erpnext/utilities/doctype/rename_tool/rename_tool.py#L44-L63) · [Attachment selection and cleanup](https://github.com/frappe/erpnext/blob/886ab6ae187244e7f1b852393384ab6019d56264/erpnext/utilities/doctype/rename_tool/rename_tool.py#L101-L118) |
| Interpret a row | The first two CSV cells are the old and new record keys. An optional third cell of `1` or case-insensitive `true` requests a merge. A missing or empty first or second cell skips the row. The worker processes the first row as data, so a header with two populated titles would become a rename attempt. Within a block, rows run in input order. Jobs for different blocks can be serviced separately. [Row reader](https://github.com/frappe/frappe/blob/199a0385c00e572664a099a57a00be6ce7404eeb/frappe/model/rename_doc.py#L673-L710) |
| Choose the destination | The source controller can revise a requested key before validation. Normal rename requires an existing source and an available destination. Merge requires an existing destination. Identical source and destination fail validation. A case- or accent-only correction is handled specially when the database finds an equivalent key with different actual spelling. The destination must pass the framework's naming rules. [Pre-rename processing](https://github.com/frappe/frappe/blob/199a0385c00e572664a099a57a00be6ce7404eeb/frappe/model/rename_doc.py#L143-L167) · [Destination rules](https://github.com/frappe/frappe/blob/199a0385c00e572664a099a57a00be6ce7404eeb/frappe/model/rename_doc.py#L346-L390) |
| Apply the change | Rename changes the primary record key and child ownership references. Merge transfers assignments to the survivor and deletes the source after the rename callback. The common path rewrites defined links and dynamic links, user settings, attachment references and version references. It invokes the destination's post-rename hook, adds an audit comment and publishes an old-to-new rename event after commit. Document-specific callbacks can add further effects. [Identity changes](https://github.com/frappe/frappe/blob/199a0385c00e572664a099a57a00be6ce7404eeb/frappe/model/rename_doc.py#L169-L232) · [Parent, children and naming field](https://github.com/frappe/frappe/blob/199a0385c00e572664a099a57a00be6ce7404eeb/frappe/model/rename_doc.py#L319-L332) |
| Report partial completion | A successful row commits individually. An exception rolls back that row, adds a failure message and permits the next row to run. Each completed block requests a search-index rebuild. The tool directs a notification to the executing user with the count of failed messages, total input rows for that block and escaped failure details. Skipped incomplete rows still contribute to the input-row count. Replaying the original CSV after a partial success can produce a missing-source error for already renamed rows. [Row transactions](https://github.com/frappe/frappe/blob/199a0385c00e572664a099a57a00be6ce7404eeb/frappe/model/rename_doc.py#L686-L710) · [Failure notification](https://github.com/frappe/erpnext/blob/886ab6ae187244e7f1b852393384ab6019d56264/erpnext/utilities/doctype/rename_tool/rename_tool.py#L77-L98) |

The form confirms queue admission and shows job counts by worker status. A job can finish with individual failures because the worker handles exceptions row by row. The reference worker identifies failures using a translated message prefix. A rebuild can expose an explicit outcome per row, localize its message for the operator and preserve the original keys, input position and merge flag. A translated label for a customer or item must continue to refer to the same identity. [User confirmation and worker counts](https://github.com/frappe/erpnext/blob/886ab6ae187244e7f1b852393384ab6019d56264/erpnext/utilities/doctype/rename_tool/rename_tool.js#L16-L75) · [Language contract](../marketplace-guides/languages/README.md)

## Register a video and refresh counts

The Video record uses its unique title for its initial record name. Title, provider, URL and description are required. The provider choices are YouTube and Vimeo. Publication date, duration and image belong to the local catalog. A distinct provider-specific ID supports tracking. The declared Desk User rights are owner-scoped, while System Manager has a separate grant. The form's playback action passes the stored provider ID when available or otherwise passes the supplied URL. [Record definition and permissions](https://github.com/frappe/erpnext/blob/886ab6ae187244e7f1b852393384ab6019d56264/erpnext/utilities/doctype/video/video.json) · [Playback action](https://github.com/frappe/erpnext/blob/886ab6ae187244e7f1b852393384ab6019d56264/erpnext/utilities/doctype/video/video.js#L4-L17)

1. For YouTube, derive the provider ID on save when the stored ID is missing or the URL changed. Accepted hosts are youtube.com, youtu.be and youtube-nocookie.com and their subdomains. A short link uses the first path segment. Embed, shorts, live and v paths use the second segment. Other forms use the first v query value. Require eleven ASCII letters, digits, underscores or hyphens. A valid ID is stored even with tracking disabled. Vimeo bypasses this ID and statistics logic. [Validation and individual refresh](https://github.com/frappe/erpnext/blob/886ab6ae187244e7f1b852393384ab6019d56264/erpnext/utilities/doctype/video/video.py#L42-L72) · [URL and ID rules](https://github.com/frappe/erpnext/blob/886ab6ae187244e7f1b852393384ab6019d56264/erpnext/utilities/doctype/video/video.py#L114-L144)
2. Video Settings is a site singleton administered by System Manager. Tracking defaults to disabled and its frequency defaults to one hour. Enabling it requires a frequency and API key. Saving an enabled configuration checks the key through the provider's language-list service. A provider error logs the authentication failure and rejects the settings save. Saving an existing 30-minute setting converts it to one hour. The language-list request is a credentials check; it does not determine the viewer's language or the video's content language. [Settings declaration](https://github.com/frappe/erpnext/blob/886ab6ae187244e7f1b852393384ab6019d56264/erpnext/utilities/doctype/video_settings/video_settings.json#L13-L63) · [Settings validation](https://github.com/frappe/erpnext/blob/886ab6ae187244e7f1b852393384ab6019d56264/erpnext/utilities/doctype/video_settings/video_settings.py#L26-L53)
3. On a tracked YouTube video save, request its statistics and copy likes, views, dislikes and comments from the first returned item. A provider/client failure in this path logs the error and permits the local video save. The hourly maintenance job checks both the enable flag and whether enough hour boundaries have elapsed. A missing last update is immediately due. The comparison truncates both instants to the start of the hour and uses thresholds of 1, 6 or 24 hours. [Single-record refresh and schedule decision](https://github.com/frappe/erpnext/blob/886ab6ae187244e7f1b852393384ab6019d56264/erpnext/utilities/doctype/video/video.py#L54-L102) · [Hourly registration](https://github.com/frappe/erpnext/blob/886ab6ae187244e7f1b852393384ab6019d56264/erpnext/hooks.py#L523-L532)
4. The batch operation checks write permission on Video Settings. It selects YouTube records with a stored provider ID, sends up to 50 IDs per request and applies the four integer counters by returned ID. A missing metric within a returned statistics object becomes zero. An ID absent from the response gets no write. A provider request exception is logged and its batch can be skipped; an unhandled client-construction or write failure can still propagate. After the batch operation returns, the scheduler records the current time. This timestamp identifies an attempted cycle and can advance even if a provider request failed inside it. [Batch selection and updates](https://github.com/frappe/erpnext/blob/886ab6ae187244e7f1b852393384ab6019d56264/erpnext/utilities/doctype/video/video.py#L147-L193) · [Timestamp update](https://github.com/frappe/erpnext/blob/886ab6ae187244e7f1b852393384ab6019d56264/erpnext/utilities/doctype/video/video.py#L75-L82)

## Acceptance examples

| Input | Expected observation | Evidence level |
|---|---|---|
| Rename A to B, request a rename that raises an error, supply one incomplete row, then merge C into D using TRUE | Three calls to the record operation, two commits, one rollback and one search rebuild request. Only the last call carries the merge flag. | Source-derived acceptance case for the release row loop. |
| Submit 501 valid rename pairs in one attached CSV | The committed request schedules blocks of 500 and 1. A failure in the first block cannot undo a committed row in the second. Use row outcomes to determine the items still outstanding. | Proposed end-to-end case from the admission and worker code. |
| The same ID Abc_012-DEF appears as a short URL and a shorts URL, then with an unrelated hostname | Both accepted forms yield exactly Abc_012-DEF. The unrelated hostname yields no parsed ID. The public validator surfaces invalid input as a validation failure. | Source-derived parser and validator case. |
| Six-hour tracking last ran at 06:55. The scheduler checks at 11:59 and 12:01 on the same date | The first check is early. The second is due, although fewer than six full elapsed hours have passed at 12:01. | Source-derived clock-boundary case. |
| The provider returns 70 views for one ID and omits another ID. A German-speaking operator opens the same videos after an Afrikaans-speaking editor | The first record shows 70 views and the second retains its prior counts. Both operators see the same local and provider identities. UI language affects presentation. | Proposed integrated acceptance case. |

The upstream [rename tests](https://github.com/frappe/erpnext/blob/886ab6ae187244e7f1b852393384ab6019d56264/erpnext/utilities/doctype/rename_tool/test_rename_tool.py#L14-L75) exercise attachment ownership over successive imports and row-failure notification with inline jobs. The [video tests](https://github.com/frappe/erpnext/blob/886ab6ae187244e7f1b852393384ab6019d56264/erpnext/utilities/doctype/video/test_video.py#L17-L139) supply provider fixtures, and the [settings tests](https://github.com/frappe/erpnext/blob/886ab6ae187244e7f1b852393384ab6019d56264/erpnext/utilities/doctype/video_settings/test_video_settings.py#L10-L38) cover missing credentials, video-save failure handling and frequency migration. Production provider quotas, current responses and concurrent workers require separate integration evidence.

The full upstream rename, video and video-settings suites passed in the [November reference run](reference-tests.md).
