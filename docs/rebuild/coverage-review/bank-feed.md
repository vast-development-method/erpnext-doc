# Linked bank accounts and statement imports

A bank feed turns provider movements into submitted Bank Transaction records that an accountant can reconcile against payment vouchers. The feed has three distinct identities: the institution holding the connection, the linked Bank Account belonging to a company, and the provider's individual transaction. The reference adapter is Plaid at ERPNext v16.60.0. Its language, country and protocol settings describe this adapter revision. [Configuration and link exchange](https://github.com/frappe/erpnext/blob/886ab6ae187244e7f1b852393384ab6019d56264/erpnext/erpnext_integrations/doctype/plaid_settings/plaid_connector.py#L11-L69)

## Import a statement window

The hourly maintenance job enters automatic synchronization when both the enabled and automatic-sync flags are set. The manual enqueue operation checks settings access and queues one job per enabled company Bank Account with a nonblank integration ID. For each account, the first window starts twelve calendar months before today; later windows begin on the stored integration date and end today. For an account-specific request, every provider page uses the same account filter. The offset is the number of rows already collected. Stop when the collected count reaches the latest reported total or the provider returns an empty page. | Provider fact | Bank Transaction projection |
|---|---|
| Account and transaction identity | The row resolves the local Bank Account by provider account ID. A previously stored provider transaction ID skips creation. The import lookup and duplicate check use the site database; their predicates do not include company or bank. A replacement supporting overlapping provider IDs needs an explicit mapping and uniqueness scope. |
| Settlement and date | A pending row is skipped. Import the provider date when the row is eligible for creation. A repeated ID already in storage does not update its previous values. |
| Amount and currency | A nonnegative amount becomes a withdrawal. A negative amount becomes a deposit of its absolute value. Carry the provider ISO currency code. On validation, a populated transaction currency must agree with the currency on the linked bank GL account when that account exists. |
| Classification and reference | Take transaction code, then payment method for the type. Choose cheque number, payment reference, then provider name for the reference. Store the original provider name as the description. Category strings and a supplied category ID can become tags. |
| Reconciliation | Insert and submit the Bank Transaction, then attach tags. Allocated amount is the sum allocated to linked vouchers. Unallocated amount is the absolute difference between withdrawal and deposit less the allocated amount, rounded at field precision. A submitted positive unallocated amount gives Unreconciled. A subsequent voucher allocation can change this status. |

## Progress, partial failure and replay

Process the returned rows in reverse sequence. Give each row a savepoint. A failure rolls back that row, records the affected account and transaction ID in the log, and allows later rows to proceed. If at least one row was inserted, the stored integration date becomes the date of the **last successfully inserted row in processing order**. Duplicate, pending, failed and empty-only windows leave the stored date unchanged. This rule depends on provider ordering and successful inserts. A failed older row can fall outside the next normal window. A rebuild that guarantees eventual recovery should record failed identities or replay an explicit earlier window. The reference adapter logs a reconnection requirement if the provider reports that the bank login must be renewed. [Progress and per-row rollback](https://github.com/frappe/erpnext/blob/886ab6ae187244e7f1b852393384ab6019d56264/erpnext/erpnext_integrations/doctype/plaid_settings/plaid_settings.py#L211-L254) · [Relink condition](https://github.com/frappe/erpnext/blob/886ab6ae187244e7f1b852393384ab6019d56264/erpnext/erpnext_integrations/doctype/plaid_settings/plaid_settings.py#L257-L281)
