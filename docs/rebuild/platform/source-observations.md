# Isolated reference observations

Twenty-eight acceptance cases were also exercised against six decision functions from the exact foundation revision. The [observations](source-observations.json) record the mapped outcome and side effects for every case. Each case ID resolves in the [typed case set](acceptance.json). This is reference execution at a single decision boundary. The larger [decision suite](verification.md) also checks rules that were verified through static inspection.

| Reference boundary | How the input was realized | What was observed |
|---|---|---|
| Self-approval | Supply the administrator or ordinary actor, a synthetic document owner and the transition's self-approval setting. | Actual Boolean approval decision. |
| Bulk approval | Serialize the specified number of unique document names. Record calls at the inline executor and queue ports and turn validation rejection into a captured exception. | Inline versus queued call count, passed document count and background timeout for queue cases. |
| Site time budget | Supply consumed and limit values in microseconds and intercept rejection on the limiter instance. | Whether admission set the rejected flag and raised rejection. |
| Event claim | Return one synthetic subscription from the lock-and-fetch port, freeze the clock, and capture updates to the subscription and its existing resume row. | Match count, changed status, payload retained or discarded, and number of resume updates. Each wake refers to the existing row and the fixed current time. |
| Processed trigger settlement | Supply the observed run status and record delete and status-update calls using a fixed row identity. | Exactly one deletion or status write, including failed/skipped value and target identity. |
| Private reference reuse | Supply matching records under a canonical private address. Set record owners and grant read on the designated row for the positive case. Capture the file controller's permission decision. | Lookup constrained to the canonical private resource, controller read checks, and continuation or denial. |

For each reference function, read its containing file directly from the pinned Git commit, select the declared function body and retain the original decision statements. The witness includes the UTF-8 SHA-256 of the exact source segment from its function definition through its last body statement, excluding leading decorators, the final newline and leading indentation on the first line only. Execute the body with the port substitutions above, bypassing outer registration decorators. Compare its result and side effects to the independently specified expected case. These checks do not establish locking behavior, queue delivery, framework initialization, permission derivation by the storage engine or integration with a live provider. The runtime tests in the [automation](automation.md), [request](record-services.md) and [work dispatch](work-dispatch.md) chapters cover those larger boundaries as qualification requirements.
