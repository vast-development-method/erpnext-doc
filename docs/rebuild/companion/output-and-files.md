# Printed transactions and file ownership

## Render a posted enterprise voucher

An application selects a company document and authorized print format. A designer format binds a document type to header, body, footer and layout settings. The print hooks extend framework rendering, and include print and point-of-sale client integrations. The packaged formats include Sales Invoice and Sales Order definitions. On app installation the loader discovers matching standard formats, skips preview JSON and imports the definitions. At the pinned revision it commits after each import, so installation recovery must inspect which formats already exist. [Hook registrations](https://github.com/frappe/print_designer/blob/70e40eae9d4c70dcc6d9d29b150327004419b64a/print_designer/hooks.py#L28-L98) · [Format loading](https://github.com/frappe/print_designer/blob/70e40eae9d4c70dcc6d9d29b150327004419b64a/print_designer/default_formats.py#L54-L91) · [Invoice format](https://github.com/frappe/print_designer/blob/70e40eae9d4c70dcc6d9d29b150327004419b64a/print_designer/default_templates/erpnext/sales_invoice_pd_format_v2.json) · [Order format](https://github.com/frappe/print_designer/blob/70e40eae9d4c70dcc6d9d29b150327004419b64a/print_designer/default_templates/erpnext/sales_order_pd_v2.json)

For the custom template selection service, require both a designer-enabled format and a nonempty designer body. If either is missing, the override yields no custom template. Otherwise parse the layout settings. A missing schema version means 1.0.0. Compare integer major, minor and patch segments: below 1.1.0 selects the older template; 1.1.0 and above selects the current one. For example 1.10.0 exceeds 1.1.0. Preserve the source document as the monetary authority and render its stored rounding, taxes and totals. A reprint has no journal or stock mutation.

Test a submitted invoice, its amended copy, a muted price field and a user without document access through normal print entry. A designer layout must never create its own financial posting or bypass the host print eligibility and document-state decisions. Test page breaks, language direction, fonts, header/footer placement and identical totals across a multipage print using an actual matching rendering environment. The upstream selection checks alone establish no pixel-level conformance. ## Browse a voucher's attachments

Drive lists document attachments using the tuple (attached document type, attached document name). It obtains visible File names first and then loads those files. Without a selected document, the browser can present virtual folders organised by record type and document. A fabricated folder and an actual stored File have different identities. A site file with no team is read-only in Drive. A team-row reference whose content type is File is also classified read-only. A team-managed document such as a Writer Document is native. Never copy a framework invoice attachment into a team folder merely to display it. [Listing by document](https://github.com/frappe/drive/blob/5123b66a91edcb96e07927e7ff5e2f70a3e4b7db/drive/api/list.py#L443-L489) · [Kinds and ownership](https://github.com/frappe/drive/blob/5123b66a91edcb96e07927e7ff5e2f70a3e4b7db/drive/utils/__init__.py#L21-L46)

For site files the access service delegates read to the framework and leaves comment, share, upload and write disabled. Querying another person's Drive rights requires share access, while checking team rights requires read access. Team-managed entities resolve owner, team membership, ancestor grants and public grants. A broad Drive team membership is insufficient evidence for access to a private site attachment. Qualify with two employees who can both browse a shared team but only one may read an invoice's private evidence. The visible files must follow the underlying authorization. Preserve the existing attachment and its document link after browsing.
