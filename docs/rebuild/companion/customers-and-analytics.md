# Customer synchronization and analytical access

## Helpdesk customer identities

When the customer master is available on the site and helpdesk customer synchronization is enabled, creating an ERP Customer can create an HD Customer with the customer name, mapped image and customer type. The adapter stores the helpdesk customer ID on Customer and the reciprocal customer master ID on HD Customer. The ERP hook exits if an HD Customer already links to this source or the operation is already a mirror. In the other direction, HD Customer checks both its own reference and existing matching ERP link before inserting. Mark the mirror operation while writing to prevent a callback loop. Related field updates use the explicit mapping. Ticket status, priority, assignment, support SLA and customer receivables each retain their own owner. This customer bridge does not describe ticket billing. The sync status service first checks whether the customer master is installed, then read rights for both types, then the enable switch. A caller lacking either read right receives only enabled=false. If both rights and the switch apply, report whether all customers on each side have links. The manual sync command checks write permission, checks the integration gate, and enqueues deduplicated work. The backfill matches unlinked records by name or creates counterparts according to its branches. Recover an interrupted sync by inspecting reciprocal links and permission mirrors before replaying. Matching names alone do not prove shared identity across two previously related customers. [Status and backfill](https://github.com/frappe/helpdesk/blob/e326986329341c803dd4bf094322670ad0591ca5/helpdesk/integrations/erpnext/api.py#L9-L138) · [Operator guide](https://docs.frappe.io/helpdesk/integration/erpnext)

For a rename, resolve the current linked counterpart. An unrelated record already holding the destination name on the opposite side rejects the operation. A merge into a record with an existing counterpart can cascade the merge; where the survivor has no counterpart, the existing link needs to transfer. Shared access and user permissions have mirror lifecycles, including changes to the user and applicable record type. Test one ERP customer, its linked HD customer, two users and one unrelated customer. Rename the first; a successful transaction must retain access for the intended customer pair and leave the unrelated customer's permission assignments intact. ## Insights read and publication contracts

A workbook groups its queries, charts, dashboards, folders and alerts. Model the read operation with a source, table, selected fields, effective permission user, workbook/query identity and requested aggregation. For the local site database, apply framework document, row and permitted-column semantics to the effective reader. A table with no eligible permission query yields a permission failure in this path; an accessible table with zero matching rows can legitimately return zero. External sources and uploads do not acquire site row rules through this adapter and need their own access policy. The upstream table tests compare preview names and counts with a permission-filtered document list and include UUID-keyed records. [Site table authorization](https://github.com/frappe/insights/blob/02c7e1ad09f9a4a66a8126c8fe28e0d56123529c/insights/insights/doctype/insights_table_v3/insights_table_v3.py#L510-L575) · [Column and row projections](https://github.com/frappe/insights/blob/02c7e1ad09f9a4a66a8126c8fe28e0d56123529c/insights/insights/doctype/insights_table_v3/insights_table_v3.py#L645-L722) · [Comparison cases](https://github.com/frappe/insights/blob/02c7e1ad09f9a4a66a8126c8fe28e0d56123529c/insights/tests/test_data_source_permissions.py#L37-L97)

Publication has separate decisions from data access. The chart/dashboard reach progresses from Private to Roles, Everyone and Public. An empty Roles selection has private reach. Moving between two Roles selections widens audience if the new set includes any additional role, including when it also removes another. Unknown levels count as private in the reach helper. A standard chart cannot run as owner. Public visibility changes on the chart take the owner-execution path. Check who may change the execution identity and the surrounding dashboard's published reach before exposing aggregates. A workbook grant alone cannot show which business rows underlie a displayed total.

For qualification create invoices for two companies and permit an analyst to read exactly one company's documents. Compare that user's document list with a local table preview and totals using reader execution. Repeat as the other company, and with a chart intentionally published under owner execution. Record the execution principal plus visible source keys for every total.
