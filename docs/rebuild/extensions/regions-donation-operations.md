# Regional accounts, specialist operations and shared identity

## Invoice registration under the India Compliance profile

A posted commercial invoice, its external invoice registration number (IRN), the registration log, and a linked e-waybill are different records. Verify company, billing GST identifier, place of supply, local feature settings, taxable items where required, and the company's effective registration date. Reject an existing IRN, equal company and billing identifiers, a domestic consumer invoice without a billing identifier in the inspected path, and a posting date earlier than the configured applicability date. These describe the adapter's decision tree at its pinned revision.

A duplicate provider registration triggers retrieval of the previous registration. Compare returned buyer GST identifier and invoice total with the current transaction before attaching the recovered identifier. Either mismatch is an error. For cancellation require an IRN and the acknowledgement time. The checked software guard accepts the boundary exactly 24 hours after acknowledgement and rejects later times. When the invoice also has an e-waybill, the cancellation path cancels that remotely and commits the local result before attempting remote IRN cancellation. A second-step failure thus leaves one real cancellation to preserve. On successful cancellation the invoice loses its active IRN and retains a cancellation log and status. Fiscal rules evolve; configuration, portal acceptance and the calendar of the applicable jurisdiction require separate qualification. ## US tax adapter

TaxJar configuration binds company, sales tax ledger and an optional shipping ledger. When a configured company has a known country other than United States, reject the row. Missing country is left to other validation. A supplied existing account must belong to the configured company and be a posting account. These tests run on saving settings even after a user changes the company on a pre-populated row. Test two US companies whose ledgers share the same account label, and a valid local group account. A company-specific tax template and the provider's eventual tax quote need their own trace. The statutory rate cannot be derived from the account number. ## Donations

For a Razorpay donation the provider capture includes payment identity, email, payment method and amount in paise. Validate the callback signature. Ignore events other than payment.captured and skip invoice-linked payments and descriptions indicating subscription payments. Resolve or create donor by email, create missing payment mode as necessary, store the provider ID on the submitted donation and divide by 100 for the rupee amount. A capture of 125050 paise yields 1,250.50. With automated donation accounting enabled, require the configured donation payment account and submit the payment entry using the donation account mappings and donation identity as reference. With automation disabled, do not generate this entry. The reviewed capture/creation path does not show a duplicate guard by payment ID. For a rebuild require duplicate-delivery qualification before treating a retry as safe. ## Room tariffs and farm projects

The Hotels reservation prices each night from arrival through the night preceding departure. For every chargeable day require a matching package rate; a missing day rejects the reservation. Item rate is the sum of nightly rates, item amount equals that rate × rooms, and net total sums item amounts. Two rooms at 900 then 1,100 per night cost 4,000. The existing-bookings query checks submitted reservations and treats their stored departure date inclusively, whereas the new reservation's charging loop excludes departure day. This can reject a back-to-back stay. Repeated rows for one package also need an explicit occupancy test because the running accumulator includes already-booked counts. These details describe the Hotels module path; the snapshot also contains overlapping declarations in Hospitality. [Reservation validation](https://github.com/frappe/hospitality/blob/2003ff8db7d7fbc453a9d14da0f971b9186a0b4b/hospitality/hotels/doctype/hotel_room_reservation/hotel_room_reservation.py#L16-L111)

A Crop Cycle defaults missing crop and row spacing units from Crop. On insertion create a Project with expected end = start + period − 1 days. Convert each crop task's one-based start and end offsets relative to cycle start into dated project tasks. For a ten-day cycle starting 1 April, project end is 10 April and a day-2 through day-4 task spans 2–4 April. Disease treatment tasks use the detected disease's start date; a tasks-created row flag suppresses repeated generation by that path. Scheduling tasks and posting stock/production costs are separate events. ## Telephony and CRM

For an enabled Exotel callback, correlate Call Log using provider call identity. A free callback returns without creating a call log. An existing record receives status, latest destination, duration (dial duration then conversation duration then zero), start/end time and the first available recording URL. A new one starts with the provider identity. The mapping is order-sensitive: no-answer, canceled and failed are handled before a completed call type; otherwise busy maps to Ringing. Operations should retain this mapping when interpreting agent activity. [Provider events](https://github.com/frappe/exotel_integration/blob/c1b14ba7db067db9a31d70b6e1f4883f74211689/exotel_integration/handler.py#L20-L132)

When same-site ERPNext integration and the configured synchronization mode allow, CRM Product and ERP Item can have linked identities. Resolve the counterpart by its explicit link field. User Permission and DocShare have separate mirror paths. Include counterpart record and user plus any type-specific deduplication fields. While applying a mirror, mark it so that its own lifecycle hook cannot reflect back indefinitely. A changed target can delete the old mirror, and deletion of the source removes its linked mirror. Carry the correctly scoped permissions into read operations. Explicitly test a missing counterpart and deletion of a user's share.
